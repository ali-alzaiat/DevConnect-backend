## What I do

Guide you through creating a complete backend module in the DevConnect codebase, from Prisma schema to API documentation.

## When to use me

Use this skill when adding a new domain feature that requires:
- Database model changes
- New REST endpoints
- DTO validation and Swagger documentation
- Unit and integration tests

## Steps

1. **Read the AGENTS.md** at backend root for conventions.
2. **Generate the module skeleton** using NestJS CLI:
   ```bash
   nest g module {name}
   nest g controller {name}
   nest g service {name}
   ```
3. **Define the Prisma schema** in `prisma/schema.prisma` and run `npx prisma generate`.
4. **Create DTOs** in `dto/` — add `class-validator` + `@ApiProperty()` decorators.
5. **Create entity** in `entities/` (TypeScript class matching the response shape).
6. **Implement the service** — inject PrismaService, write business logic, handle errors.
7. **Wire the controller** — add Swagger decorators, validate DTOs, call service methods.
8. **Register the module** in `app.module.ts` (auto-generated by CLI).
9. **Add auth guards** if the endpoints require authentication.
10. **Write tests**: `*.service.spec.ts` (unit) and `*.controller.spec.ts` (integration).
11. **Verify the API spec**: start the server, check `/api-yaml` for the new endpoints.
12. **Run lint + build** before committing.

## Files to Check Before Starting

- `prisma/schema.prisma` — existing models
- `src/common/` — shared services, decorators, guards
- An existing module (e.g., `project/` or `article/`) for pattern reference
- `src/app.module.ts` — existing imports
